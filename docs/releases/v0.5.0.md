# VariaQ 0.5.0 — generic binary quadratic QAOA

Release type: minor (0.4.1 → 0.5.0).

## Highlights

- **Backend-neutral `BinaryQuadraticModel`** (`variaq.bqm`) is now the canonical
  solver artifact for the generic QAOA path. It documents a sense-aware energy
  convention, validates structure, stores stable SHA-256 digests, and persists
  structured penalty metadata.
- **Generic QAOA lowering** in `variaq.lower` builds a `QAOAProblem` from any
  BQM. The same lowered representation is consumed by the Qiskit and CUDA-Q
  adapters, eliminating previous family-specific backend paths.
- **MaxCut regression preserved**: the seed-42 8-node reference expectation and
  sampled objective remain unchanged after migration to the generic path.
- **Assignment** and **Subset Selection** are now supported on the QAOA path
  when their BQM lowering is verified; exact and heuristic solvers continue to
  support all families.
- **Graph Partition** BQM lowering is implemented, but its automatic penalty
  policy is experimental for 0.5.0. It is **not advertised** in the public
  `qaoa`/`cudaq-cpu`/`cudaq-gpu` capability matrices for this release. The
  implementation remains in the tree for continued hardening.

## What is new

- Generic `BinaryQuadraticModel` with validation, `energy()`, `decode_bits()`,
  `to_dict()`, and `digest()`.
- `variaq.lower.lower_to_binary_quadratic()` for `maxcut`, `assignment`,
  `subset-selection`, and `graph-partition`.
- Sense-aware penalty construction: penalties are added with a sign that makes
  infeasible states worse than any feasible state in the source objective sense.
- Explicit penalty metadata persisted in run records, including derivation
  inputs such as `max_abs_score`, `max_abs_objective`, and `max_weight`.
- Decoding and feasibility are now explicit: every quantum sample is decoded
  through `bqm.decode_bits()` and re-evaluated by the original problem instance.
- Sample selection ranks decoded **feasible** solutions by authoritative objective,
  not raw BQM energy. Runs report `feasible_sample_count`,
  `infeasible_sample_count`, `best_solution_energy`, `best_infeasible_energy`,
  and `constraint_violations`.
- Resource guards based on binary variable count and estimated statevector memory
  before simulator execution (Qiskit: 18 variables / 512 MiB; CUDA-Q: 18 variables
  / 2 GiB).
- `variaq compare quantum` consults solver `supported_families` and works for
  every publicly supported quantum family.

## Capabilities in 0.5.0

| Family            | exact | heuristic | qaoa | cudaq-cpu | cudaq-gpu |
| ----------------- | ----- | --------- | ---- | --------- | --------- |
| maxcut            | yes   | yes       | yes  | yes       | yes       |
| assignment        | yes   | yes       | yes  | yes       | yes       |
| subset-selection  | yes   | yes       | yes  | yes       | yes       |
| graph-partition   | yes   | yes       | no   | no        | no        |

Graph Partition quantum support is kept **experimental** in 0.5.0 because the
automatic penalty policy has not yet been shown to yield reliable feasible
samples across the tested instance distribution. The BQM lowering remains
implemented and tested; future work will either harden the penalty bound or
add user-controllable penalty overrides.

## Trustworthiness checks performed for 0.5.0

   `src/variaq/__init__.py`, and `tests/test_identity.py`.
2. Exhaustive tiny-state BQM verification for assignment, subset-selection,
   and graph-partition: the global BQM optimum maps to a feasible authoritative
   optimum.
3. MaxCut generic-path regression against the seed-42 reference expectation.
4. Cross-framework Qiskit/CUDA-Q fixed-parameter equivalence for shared BQMs.
5. Decode/feasibility audit across all quantum families.
6. Capability matrix matches actual `supported_families` declarations.
7. Schema version remains `1`; all new JSON fields are additive.
8. Historical database compatibility verified by reproducing a stored MaxCut run.
9. Distribution build produces `variaq-0.5.0.tar.gz` and
   `variaq-0.5.0-py3-none-any.whl`.
10. Clean wheel install reports version 0.5.0.

## Not in this release

- No physical QPU support.
- No Triagewall, Ollama Fleet, or bb scheduling integration.
- No IBM Quantum Runtime, AWS Braket, or D-Wave remote execution.
- No automatic marketplace or plugin-store submission.
- No Graph Partition quantum support advertisement.

## Known limitations

- Graph Partition QAOA lowering exists but is experimental; automatic penalties
  need additional bounded-instance validation before public advertisement.
- GPU results use `fp32` by default and may differ from CPU `fp64` results by
  more than CPU-vs-CPU tolerance.
- Local statevector simulation limits apply (18 binary variables / qubits for
  the default QAOA backends).
- No quantum-advantage claim is made.
