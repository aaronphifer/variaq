# VariaQ 0.7.0 — Local Web UI

Release date: TBD (release-hardening complete).

## Highlights

- Optional local web interface: install with `pip install 'variaq[web]'` and
  start with `variaq web`.
- Shared `VariaQService` application layer and a versioned local JSON API under
  `/api/v1/`.
- Dashboard, problem/run/campaign detail, campaign planning and bounded
  execution, analysis charts with data tables, reports, and capabilities views.
- Safe report downloads limited to known report artifacts beneath the configured
  report root.
- Packaged Jinja templates, CSS, vanilla JavaScript, and vendored Chart.js; Node
  is not required at runtime.

## Local startup and data roots

The default server address is <http://127.0.0.1:8701>:

```bash
variaq web
```

Existing local datasets can be selected explicitly:

```bash
variaq --db /path/to/variaq.sqlite3 --problems-dir /path/to/problems \
  web --reports-dir /path/to/reports
```

The UI is local-first and has no authentication or internet-hardening claim.
Binding to a non-loopback address prints a prominent warning; use that only on
a trusted LAN and do not expose this server to the public internet.

## Campaign and report workflow

Campaign creation is plan-first. The plan displays the family, problem count,
requested run count, solver breakdown, unavailable combinations, warnings, and
the default 500-run limit before execution. Over-limit execution requires an
explicit acknowledgement and still passes through VariaQ's own max-run guard.
Execution is local, sequential, and limited to one campaign per server process.

Campaign analysis is calculated by VariaQ, not JavaScript. Charts consume the
structured analysis result and retain tabular text alternatives. Report pages
show report/campaign provenance, source-run counts, formats, and constrained
artifact downloads.

## Scientific presentation

Run pages keep decoded objective, optimized expectation, and lowered BQM energy
as distinct labeled quantities. Feasible and infeasible sample counts are shown
separately and do not determine run status. Quality and gap calculations remain
objective-sense aware in the Python analysis layer.

## Compatibility and packaging

- Python 3.12 or newer.
- Existing schema-version-`1` experiment databases remain compatible.
- The base installation does not require FastAPI, Jinja2, or Uvicorn.
- Linux and Windows CI exercise the web/API test suite; CUDA-Q, a GPU, and a
  physical QPU are not required.
- The wheel contains all templates and static assets needed by the installed
  server.

## Known limitations

- Task progress is in memory. If the server stops during a campaign, recorded
  runs remain durable but the progress entry is lost.
- There are no accounts, collaboration features, remote workers, or remote
  quantum providers.
- Charts currently cover campaign scaling analysis only.
- The UI is a local research interface, not a hardened multi-user web service.

## Explicit non-goals

No Triagewall integration, Ollama Fleet integration, bb scheduling logic,
physical-QPU execution, remote quantum provider, or `bb-plugin-variaq` change is
part of this release.
