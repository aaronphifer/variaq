Objective gap · Feasibility

How to read these comparisons

Quality summaries include only successful, feasible, authoritatively evaluated runs of this instance. Achievement includes selected exact runs and uses only runs with a consistent selected exact reference: the objective must be within 1e-9 of that optimum. Its denominator is shown explicitly. Relative gaps can be undefined for a zero optimum even when absolute gaps exist.

Each chart row is a descriptive mean within one solver, backend/version, configuration, precision, warmup mode, benchmark execution, environment and timing scope. Seeds and candidate angles may vary across repeated searches; exact controls and source run IDs remain available below. These summaries do not establish paired experimental controls. Pairing still requires the same canonical problem, benchmark execution and repeat slot.

Wall time includes the solver call and setup; persistence is excluded for current records. Compute and warmup scopes are solver-specific. Search and expectation times overlap; layers must not be added. Historical scopes may be unknown. Failed, infeasible and unevaluable records are excluded from these quality and timing row summaries. Missing values stay unavailable, never zero. No speedup ratio is inferred.

Scaling retains existing per-instance repeat timing summaries, whose successful timing observations can include infeasible solutions; each point’s count and controls are in its data table. It keeps distinct instances and configurations as separate points. A bounded window can split repeat pairs; use an instance filter for focused evidence. Size and warmup filters apply within the labelled window. All quantum backends are local simulators; no physical QPU or quantum advantage is established.
